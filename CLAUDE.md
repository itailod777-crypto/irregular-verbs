# Standing rules

## Expectation alignment before any project (התאמת ציפיות)

Whenever the user asks for a project (or any substantial build/change):

1. **Do not start building.** First write an expectation-alignment summary to the user, in Hebrew:
   - What I understood the request to be
   - Scope: what will be included / what will not
   - Deliverables and form (files, pages, features)
   - Assumptions and open questions
   - How we'll know it's done
2. **Wait for the user's explicit approval** of that summary.
3. Only after approval, implement the project according to the approved expectations.

This rule is permanent and applies to every new project request.
